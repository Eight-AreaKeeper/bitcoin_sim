# 简化版比特币模拟（学习用）

用纯 Python（只依赖标准库，Python 3.8+）从零实现一个简化版比特币，分 4 个阶段，每个阶段都能单独运行、打印出可观察的演示过程。代码里有详细的中文注释，建议按顺序边读代码边跑。

```
python stage1_blockchain.py      # 阶段 1：区块、哈希链、PoW、链校验
python stage2_utxo.py            # 阶段 2：UTXO 交易 + 签名验证
python stage3_difficulty.py      # 阶段 3：难度调整、区块奖励减半（加 -v 看每个块）
python stage4_network.py [种子]   # 阶段 4：多节点广播、分叉、最长链、网络分区与双花
python crypto.py                 # 小自测：ECDSA 签名/验签
```

每个脚本运行时间都在几秒以内。

## 文件结构

| 文件 | 内容 |
|---|---|
| `crypto.py` | 双重 SHA-256、手写 secp256k1 椭圆曲线 + ECDSA 签名/验签、公钥→地址 |
| `stage1_blockchain.py` | `Block`、`Blockchain`、挖矿、链校验、篡改演示 |
| `stage2_utxo.py` | `TxIn/TxOut/Transaction`、`UTXOSet`、`validate_transaction`、`Wallet`、默克尔根 |
| `stage3_difficulty.py` | 共识参数 `Params`、带难度目标的 `Block`、支持分叉/重组的完整版 `Blockchain` |
| `stage4_network.py` | 离散事件网络模拟器 `Network`、节点 `Node`（独立的链/内存池/钱包） |

后面的阶段会 import 前面的代码：阶段 3 复用阶段 2 的交易和 UTXO，阶段 4 每个节点内部就是一条阶段 3 的链。

## 阶段 1：哈希链 + 工作量证明

- 区块头包含上一个区块的哈希 `prev_hash`，所以区块串成链。
- 挖矿 = 不断改 `nonce`，直到 `hash < target`。难度每加 1 比特，平均尝试次数翻倍。
- 链校验检查三件事：哈希是否和内容一致、是否满足 PoW、`prev_hash` 是否接得上。
- 演示里篡改区块 #2 后：只改数据 → 哈希不符；重算哈希 → 不满足 PoW；重挖 #2 → #3 接不上；必须把后面全部重挖。

## 阶段 2：UTXO 与签名

- 没有账户余额，只有一个个“未花费输出”。余额 = 属于你的 UTXO 之和。
- 交易花掉旧 UTXO，生成新 UTXO；输入 − 输出 = 手续费；多出来的钱要自己写一个“找零”输出。
- 花一个 UTXO 需要：公钥（其哈希 = UTXO 上的地址）+ 对整笔交易（不含签名）的签名。
- 每个区块第一笔是 coinbase，凭空产生“区块奖励 + 手续费”。
- 演示了 5 种被拒绝的作弊：冒用别人的 UTXO、伪造签名、签名后篡改收款人、凭空造币、双花（同块和跨块）。

## 阶段 3：难度调整与奖励减半

- `target` 越小越难，`难度 = 2^256 / target` ≈ 平均尝试次数。
- 每 `retarget_interval` 个块：`新 target = 旧 target × 实际用时 / 期望用时`，单次最多 4 倍。
- 用“模拟算力”：每尝试一次哈希，模拟时钟走 `1/算力` 秒，所以出块用时由真实的尝试次数决定。
- 演示中算力 200 → 800 → 100 H/s 变化，可以看到难度跟着变、出块间隔回到 10 秒附近。
- 奖励每 `halving_interval` 块减半，总量上限 ≈ 初始奖励 × 减半间隔 × 2（比特币：50 × 210000 × 2 = 2100 万）。
- 这里的 `Blockchain` 保存整棵区块树，按**累计工作量**（不是块数）选主链，支持链重组。

## 阶段 4：多节点、分叉、最长链

- 离散事件模拟：全局模拟时钟 + 事件队列，消息按链路延迟送达。同一个随机种子结果完全可复现。
- 每个节点只通过消息了解别人：新块、新交易都用泛洪广播；收到父块未知的块就向发送方要父块。
- 挖矿时间按指数分布抽样（PoW 是无记忆的），到点后真的算出 nonce，所以其他节点能真实验证。
- **场景 1：自然分叉**。5 个节点，链路延迟 1~4 秒、出块 10 秒，经常两个节点几乎同时出块。日志会显示“坚持先收到的”、“链重组”，最后全网收敛到同一条链，并列出所有被淘汰的陈旧块。
- **场景 2：网络分区 + 双花**。A 组（算力 350）和 B 组（算力 100）被断开，N0 用同一个 UTXO 在 A 组付给 N1、在 B 组付给 N3。分区期间两边都“确认”了自己的那笔；恢复后 B 组整条链被放弃，付给 N3 的交易因输入已被花掉而被丢弃。

换个种子会看到不同的分叉：`python stage4_network.py 42`

## 和真实比特币的主要简化

- 序列化用 JSON/字符串，不是比特币的二进制格式；地址用 SHA-256 前 20 字节，不是 Base58Check(RIPEMD160(SHA256))。
- 没有脚本系统（Script），“锁定/解锁”直接写死成“地址 = 公钥哈希 + ECDSA 签名”。
- 所有输入签同一个 sighash（相当于 SIGHASH_ALL 的简化版）；签名用随机 k，不是 RFC 6979。
- 时间戳只要求晚于父块（比特币是“晚于过去 11 块的中位数，且不超过网络时间 + 2 小时”）。
- 没有 coinbase 成熟期（比特币要求 100 个块后才能花）、没有区块大小限制、没有手续费优先级。
- 每个区块后直接保存一份 UTXO 快照，方便分叉时取用；真实节点只存一份 UTXO，靠撤销数据回滚。
- 难度窗口取父块往前若干块，与比特币的 2016 块窗口（还带着一个著名的差一错误）略有不同。
- 手写的 ECDSA 只为教学，没有防侧信道，不能用于真实资金。

## 可以继续尝试的实验

- 阶段 4 场景 2 里把 B 组算力调到超过 A 组（`hashrates=[60, 40, 40, 150, 100]`），看看“51% 攻击”如何让双花成功。
- 把场景 1 的 `latency_range` 调小或把 `block_time` 调大，观察分叉率下降。
- 实现“自私挖矿”：让某个节点挖到块先不广播，等别人追上再放出来。
